# 페이지 재구성 계획 (허브 + CCTV 하위 페이지)

> 상태: **보류** — 애드센스 심사 통과 후 착수. 심사 중 URL/구조 변경은 반려 위험.
> 작성: 2026-09. 논의 배경은 대화 로그 참고.

## 왜 하는가

- 지금은 `index.html` 한 페이지에 9개 섹션이 몰려 있음. 콘텐츠가 늘수록 길어지고,
  하나의 URL이 여러 검색어를 놓고 자기들끼리 경쟁함.
- 목적지별 페이지로 나누면 "스타필드 하남 실시간 CCTV", "코스트코 하남 주차" 같은
  롱테일 검색어를 각각 노려 **검색 유입(세션) 자체가 증가**.
- 광고 수익의 지배 변수는 "페이지당 광고 수"가 아니라 **세션 수**.
  이 사이트는 확인하고 나가는 유틸리티라 세션당 페이지뷰는 어차피 ≈1.
  → 한 페이지에 몰아넣기(광고 스터핑)보다 멀티페이지 SEO가 총수익에 유리.
- 멀티페이지 + 명확한 내비 + 내부 링크는 애드센스 심사에도 "진짜 사이트" 신호.

## 치명적 리스크 (반드시 회피)

- **얇은 페이지 금지**: CCTV 임베드 + 표 몇 줄짜리로 쪼개면 "짜깁기·저품질"로 반려.
  각 페이지는 혼자서도 완결 = 원문 **500~800자 이상** + 카메라 + 혼잡 패턴표 +
  주차(요금·시간·진입로) + 대중교통 + 계절/행사 + 팁 + 그 장소용 FAQ + 소개 문단.
- **스텁 페이지 금지**: "준비 중" 페이지 공개 = "제작 중 사이트"로 반려.
  콘텐츠·카메라가 준비된 페이지만 배포.
- **목적지 하나를 또 잘게 쪼개지 말 것** (스타필드를 다시 3페이지로 등).
- **심사 중 배포 금지.**

## 목표 URL 구조

정적 사이트라 폴더 + index.html 로 깔끔한 주소 (Cloudflare Pages 자동 처리):

```
hanamlife.com/                     허브: 소개 + 목적지 카드 + 종합 혼잡 캘린더
                                        + 자주 묻는 질문 + 제보·건의·제휴 + 업데이트 로그
hanamlife.com/cctv/starfield/      스타필드 하남
hanamlife.com/cctv/misa/           미사·조정경기장
hanamlife.com/cctv/hanam/          하남 진출입 (고속도로·팔당대교)
hanamlife.com/cctv/costco/         코스트코 하남      (카메라·콘텐츠 준비되면)
hanamlife.com/cctv/ikea-gangdong/  이케아 강동        (하남 인근 카테고리, 보류)
hanamlife.com/cctv/all/            (선택) 전체 카메라 한눈에
hanamlife.com/privacy.html
hanamlife.com/terms.html
```

## 각 CCTV 페이지 필수 요소

- 고유 `<title>`, `meta description`, `link rel=canonical`, `og:*` / `twitter:*`
- `assets/og.png` 대신 페이지별 OG 이미지 있으면 더 좋음 (없으면 공용 사용)
- 상단 **브레드크럼**: 홈 › 교통 CCTV › 스타필드 하남
- **형제 페이지 링크** (다른 목적지로 이동)
- JSON-LD: `WebPage` + `BreadcrumbList` (가능하면 `Place`)
- `sitemap.xml` 에 전부 등록, `lastmod` 갱신
- 공통 `<head>`(AdSense `ca-pub-9635871358308305`, GA4 `G-Y46YYZLMCK`, favicon) 포함
- 푸터: 개인정보처리방침 · 이용약관 · 연락처

## 허브(Main) 페이지

- 얇아지지 않도록 콘텐츠 유지: 사이트 소개, 이용 방법, CCTV 화면 읽는 법,
  하남 도로 개요(또는 별도 `/roads/` 로 분리), 종합 혼잡 캘린더, FAQ, 제보, 업데이트 로그
- 목적지 카드: 이름 + 한 줄 설명 + (가능하면) 혼잡 힌트 + 페이지 링크

## 광고 배치 (승인 후)

- 페이지당 **2~3개**: 소개 문단 직후(첫 화면 근처, 콘텐츠 밀어내지 않기),
  본문 중간, 하단. 콘텐츠 비중 > 광고 비중 유지.
- **모바일 앵커(하단 고정) 광고** 1개 — 유틸리티 사이트 RPM 최고 자리. 자동 광고에서 활성화.
- CCTV 플레이어·광고는 **지연 로드**로 페이지 속도 유지 (Core Web Vitals = 순위 = 트래픽).
- `docs/index.html` 등의 `<div class="ad">` placeholder 를 실제 광고 유닛 코드로 교체.

## 유지보수

- 페이지 증가 → `<head>`(AdSense·GA4·OG)·푸터 중복. 5~6개면 복붙 감당 가능하나,
  공통 스니펫을 작은 JS include(예: `assets/js/partials.js`)로 빼면 관리 편함.
- `cams.js` 토큰 6시간 자동 갱신은 페이지를 쪼개도 그대로 동작.
- `player.js` 는 페이지별로 필요한 `data-deck` 만 마운트하도록 확인.
- 새 목적지 카메라는 `tools/list-cams.mjs` 로 반경 내 후보 조회 후 `cams.js` 에 추가.

## 실행 순서

1. 애드센스 **승인 메일 확인** (필수 선행)
2. `git checkout -b restructure` — 작업은 이 브랜치에서만, `main` push 금지
   (main push 시 즉시 배포되므로)
3. `/cctv/*` 페이지 생성, 허브 재작성, 내부 링크·브레드크럼·sitemap 갱신
4. 리다이렉트: 기존 앵커(`/#starfield` 등)로 유입되던 것 고려.
   `index.html` 앵커는 유지하거나 새 페이지로 안내. 기존 URL은 그대로 살아있음(홈).
5. 로컬 미리보기(`.vscode` tasks)로 전체 링크·레이아웃 점검
6. `main` 에 머지 → 한 번에 배포
7. 구글 서치콘솔·네이버: 새 URL `URL 검사 → 색인 요청`, sitemap 재제출
